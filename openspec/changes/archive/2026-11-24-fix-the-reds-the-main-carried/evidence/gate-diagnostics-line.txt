The mechanism, in the file's own terms
=====================================

`DiagnosticsLog.readEntries()` returns `file.readLines()`, and the retention pass ages a line by its leading
timestamp and drops a line it cannot parse (`aged++`, `DiagnosticsLog.kt:600–631`). A message whose text carries
newlines is therefore written as several lines: one head with the timestamp and continuation lines without one.
The reader returns each as a separate entry, so the screen pages them as separate rows — and the retention pass
deletes the continuation lines, so an exported log loses them too. The fold is at the single write seam
(`timestamped`), so every writer — the worker batch, the crash handler's direct write and the retention report —
gets it.
