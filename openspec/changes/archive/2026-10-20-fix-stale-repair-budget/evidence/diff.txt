+## Root cause
+
+`tools/issues/resolve-stale.sh:190` (base `9e7e969`) spends a slot of the run's bound as soon as an item is
+*reachable* for the repair ladder — `due=$((due + 1))`, before the two token loops classify anything — while
+the write that was supposed to justify the slot happens at `:236` (repair) or `:248` (park) and needs `repairs`
+or `unresolved` to be non-empty. The suffix loop's ambiguous branch (`:203`) fills neither: it counts the
+ambiguity (`ambiguous`, `item_ambiguous`) and `continue`s, because an ambiguity is reported, never guessed
+(D4). So the reachable-but-unwritable case has no write, yet has already paid, and `:168`'s `while … "$due" -lt
+"$max_items"` stops the walk there. Run 39296403233: `due=25 repaired=4 parked=5 ambiguous=22 waiting=66` —
+16 of the 25 visited items produced no write, the `ambiguous=22` counts tokens.
+
+One mechanism, not two: the bound is charged against a property the run cannot know it has until after the
+work that would justify it.
+
+## The single fix
+
+Move the charge to where the evidence is:
+
+```bash
+if [ -n "$repairs" ] || [ -n "$unresolved" ]; then due=$((due + 1)); else skipped=$((skipped + 1)); fi
+```
+
+placed between the token loops and the two write branches, and delete the `due=$((due + 1))` at `:190`. The
+bound now counts the items a run acts on — a repair or a park, and in the default dry run the items it would
+act on; an item the ladder can only report is visited, accounted `skipped`, and costs nothing — so the walk
+continues to the next item. `read = due + skipped + waiting` still accounts for every
+issue in the tracker, `ambiguous` still counts every ambiguous token, and the write branches are untouched:
+nothing is rewritten, parked or commented for an ambiguous citation.
+
+The `skipped` counter was already the "visited, nothing to write" bucket (an item with no stale token, and a
+parked one), so no new counter and no new line format is introduced: the run's summary line keeps its shape.

+## Why
+
+The scheduled repair (`.github/workflows/sensors.yml:118`, `bash tools/issues/resolve-stale.sh
+"$SENSORS_MODE" --max-items 25`) spends its bound on items it can only report. Run 39296403233
+(2026-10-19T17:42Z) ended `read=173 due=25 repaired=4 parked=5 ambiguous=22 skipped=82 waiting=66 writes=18`:

+**Root cause.** `due` is incremented from *reachability for a repair*, not from the write that follows it:
+`tools/issues/resolve-stale.sh:190` (base `9e7e969`) does `due=$((due + 1))` right after the parked/skip

+spent before it is known whether the run can write anything for the item.** An ambiguous-only item therefore
+consumes a slot of every run for ever, and `:168`'s `while … "$due" -lt "$max_items"` stops the walk at the
+head of the queue.

+# stale-citation-resolution — deltas
+
+## MODIFIED Requirements
+
+### Requirement: The resolver runs on its own, bounded and idempotent
+
+The resolver SHALL run without a person, in the checks' own pipeline under that pipeline's least privilege,
+SHALL be bounded per run, SHALL default to a dry run, and SHALL be idempotent. The bound SHALL be spent only
+on the items the run acts on — a repair or a park, and in a dry run the items it would act on — so an item
+the ladder can only report cannot consume the run's budget, and SHALL never hide the items it did not reach:
+the run SHALL report how many wait. The count of unresolved citations SHALL be a declared check row, so a
+growing residue is a measurement.
+
+#### Scenario: A scheduled run repairs without a person
+
+- **WHEN** the pipeline runs on its schedule
+- **THEN** the citations it can repair are repaired, and the items are eligible again
+- **Case**: `pipeline#scheduledRunRepairs`
+
+#### Scenario: The bound holds
+
+- **WHEN** more items are due than the run's bound allows
+- **THEN** the run repairs the first ones, reports how many wait, and the next run continues
+- **Case**: `resolver#boundHoldsAndReportsTheRest`
+
+#### Scenario: The bound is spent where the tracker changes
+
+- **WHEN** an item's only stale citation is ambiguous, so the ladder can report it but write nothing for it
+- **THEN** the item costs no slot of the run's bound, the items behind it in tracker order are still reached,
+  and the ambiguity is still counted and still writes nothing
+- **Case**: `resolver#ambiguityDoesNotConsumeTheBound`
+
+#### Scenario: A second run changes nothing
+
+- **WHEN** the resolver runs again over items it already processed
+- **THEN** no citation is rewritten, no comment is posted, and the run reports an empty working set
+- **Case**: `resolver#secondRunChangesNothing`
+
+#### Scenario: The residue is a declared check
+
+- **WHEN** citations remain unresolved
+- **THEN** a registry row reports their count as its measurement, so the pile cannot grow unobserved
+- **Case**: `pipeline#residueIsADeclaredRow`
