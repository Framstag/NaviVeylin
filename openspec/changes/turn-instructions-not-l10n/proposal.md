## Why

Turn-by-turn instruction text ("Turn left", "Exit 3", "Enter motorway", "Keep left") is generated by the native JNI bridge (`OSMScoutClient.cpp` in the libosmscout submodule) in hardcoded English and passed through to the UI verbatim. On a German device the Android Auto host instruction panel, the Auto route-description screen, and the phone next-turn overlay all render English instructions. The i18n-l10n spec already mandates that every user-facing string be translatable and that German be fully supported — turn instructions are the remaining gap.

## What Changes

- Add a Kotlin-side localizer (`TurnInstructionLocalizer` in `:core`) that rebuilds instruction display text from the structured fields the JNI bridge already exposes (`turnType`, `streetName`) using Android string resources, with the native English text as fallback for unknown turn types.
- Add the instruction strings to `:core` resources (`values/` English default + `values-de/` German), keeping the native layer unchanged (same pattern the i18n-l10n spec already pins for POI category names).
- Wire the localizer into:
  - Auto host instruction panel cue + next-step cue (`NavigationTemplateMapper.stepForInstruction`)
  - Auto route-description screen rows (`routeDescriptionRows`)
  - Phone next-turn overlay (`NextTurnOverlay`, including the next-next hint)
- Disambiguate maneuvers the bridge does not expose as a distinct `TurnType` (motorway change/leave reuse the plain move types) and the roundabout exit count (embedded in the English "Exit N" text) by parsing the stable native English strings; fall back to the native text if a pattern is ever unrecognized.
- Add unit tests: localizer mapping (English + German), Auto template cue localization, and German translation completeness for the new `:core` resources.

## Capabilities

### New Capabilities

- `turn-instruction-localization`: Localized turn-by-turn instruction text for phone and Android Auto, rebuilt from structured navigation data in the frontend with the native layer unchanged.

### Modified Capabilities

- `i18n-l10n`: Extends the "All user-facing text is translatable" requirement to cover native-generated navigation instruction text (turn instructions), which previously bypassed the resource system.

## Impact

- `core/src/main/java/com/naviveylin/core/TurnInstructionLocalizer.kt` (new) + `core/src/main/res/values(-de)/strings.xml` (new)
- `auto/.../NavigationTemplateMapper.kt` — `stepForInstruction`/`routingInfoFromState` gain a `StringResolver` parameter; `routeDescriptionRows` localizes text
- `auto/.../NavigationScreen.kt` — passes the car-context resolver
- `app/.../ui/navigation/NextTurnOverlay.kt` — localizes description/shortDescription and next-next hint
- Tests: `core` localizer + completeness tests; `auto` `NavigationTemplateMapperTest` updated
- No native/submodule changes; no new dependencies
