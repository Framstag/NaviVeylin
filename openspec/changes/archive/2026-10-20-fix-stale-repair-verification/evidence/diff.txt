+## Root cause
+
+A repair is counted, and commented, from the fact that a rewrite was *attempted*. `tools/issues/resolve-stale.sh`
+(base `648d2bc`) accumulates a human bullet in `repairs` for every token the ladder resolves (`:209`, `:225`), and
+every consequence is gated on that variable being non-empty: the due charge (`:244`), the body write and the
+`citation repaired` comment (`:249`–`:252`), the `writes` count (`:253`) and `repaired=$((repaired + 1))`
+(`:255`). Nothing compares the produced body with the input, and nothing re-classifies the token.
+
+The attempt becomes a *no-op* through the basename half. `tools/issues/rewrite.awk:18` refuses a match whose left
+character is `[A-Za-z0-9_.-]` and whose right one is `[A-Za-z0-9_]`; `/` is deliberately outside both classes,
+because a full path such as `old/Place.kt` legitimately follows a separator. So when the body cites both a
+doubled-directory token `D/D/f` and the bare name `f`, the suffix loop rewrites `f` **everywhere** — including at
+the tail of `D/D/f`, which becomes `D/D/D/f`. The absent loop then looks for `D/D/f`, finds it starting at the
+second segment of `D/D/D/f` (preceded by `/`, which the same rule admits), collapses it, and writes `D/D/f`
+back. The body leaves the loops byte-identical to its input while `repairs` holds two bullets — the measurement
+the apply run of 2026-10-19 shows: `repaired=14`, of which 4 bodies were never written.
+
+One mechanism, not two: the run reports the attempt, never the change. The boundary gap is only the way an
+attempt is manufactured that changes nothing; the accounting is what makes it a false report.
+
+## The single fix
+
+Two guards, both of them the same rule — *a repair is a change to the record*:
+
+1. `tools/issues/rewrite.awk` takes `-v standalone=1`, which additionally refuses a match preceded by `/`. The
+   suffix loop passes it, so a basename repair rewrites only an occurrence that stands as its own citation and
+   never the tail of a longer path. The absent loop writes full paths and keeps the rule unchanged, so nothing
+   about its boundary behaviour moves.
+2. The two loops record pairs (`old` → `new`) instead of bullets. After both loops, a pair is kept only when all
+   three hold — the body differs from the input, `issues_citation_class "$new"` is not `absent`, and the old
+   token is not present in the new body as an `absent` citation (asked of `issues_citation_matrix_of "$new_body"`,
+   so a token that survives *inside another path* is caught while the target path that now legitimately contains
+   its own name is not). Kept pairs compose `repairs`; a failing pair becomes an `unresolved` bullet naming what
+   failed, so the item takes the park branch with its reason instead of the repair branch with a false claim.
+
+Guards 1 and 2 are not alternatives: 1 alone leaves the accounting lying about any other no-op (a successor the
+rename map names but the tree no longer holds — red case 3), and 2 alone turns a repairable item into a park
+because the cancellation it detects was manufactured by the other half (red case 1, which asserts the *written*
+body and would see no body write at all). The park is the honest fate: the script's header states that a refusal
+recorded nowhere is the defect this tool exists to fix (#163), so an item whose citation stays stale is parked
+with a reason rather than silently skipped.
+
+The `due` guard keeps its place and now charges verified repairs only, which is `#199`'s rule unchanged in
+substance: an item the run writes nothing for costs no slot.
+
+## Blast radius
+
+`tools/issues/resolve-stale.sh` (pair collection in both loops, one verification block, `repairs` composed after
+it, comments), `tools/issues/rewrite.awk` (one flag and one condition), `tools/resolve-stale-cases.sh` (three
+cases, one helper), `tools/resolve-stale-mutations.json` (one search string follows the changed line, three records
+added), the spec delta. No compiled file, no change to the classifier, the ladder, the parking rule, the
+ambiguity rule, the bound's semantics or the residue metric's measurement.
+

+# fix-stale-repair-verification
+
+## Why
+
+The scheduled repair reports repairs the tracker does not hold. Measured on the applying run of 2026-10-19
+(`bash tools/issues/resolve-stale.sh --apply --max-items 200`, `due=22 repaired=14 parked=3`), **4 of the 14
+"repaired" items were still classified `absent` afterwards**: #181 and #182 (the doubled form of
+`tools/issues/close.sh` and of `tools/issues/update.sh`), #196 (the doubled form of
+`tools/sensors/metrics/coverage.sh`) and #16 (a doubled `guidelines/` prefix). #181's timeline carries the
+`citation repaired for the repository's own record` comment and **no `edited` event** — the body was never
+written.
+
+**Root cause.** A repair is counted, and commented, from the fact that a rewrite was *attempted*, never from the
+record changing: `tools/issues/resolve-stale.sh:255` (base `648d2bc`) does `repaired=$((repaired + 1))` on
+`[ -n "$repairs" ]` alone, `:253` counts the write `gh` is handed, and the comment at `:250` is posted from the
+same variable — no comparison of the produced body with the input, no re-classification of the token. The
+basename half makes the attempt reachable as a no-op: the suffix loop (`:208`) rewrites a bare citation
+**everywhere**, including inside a doubled token, because `tools/issues/rewrite.awk:18` treats `/` as a
+boundary and so rewrites `close.sh` at the tail of `tools/issues/tools/issues/close.sh`. The token gains a third
+copy of its directory, and the absent loop (`:224`) then collapses the doubled form — which still occurs inside
+that triple — back to exactly what it was. The two rewrites cancel: the body comes out of the loop byte-identical
+to its input, and the run reports a repair for it.
+
+**Red tests on HEAD** (`648d2bc`), added to `tools/resolve-stale-cases.sh` and each failing for its own reason
+(2026-10-20T10:15:00Z, `evidence/red.txt`):
+
+- `resolver#basenameRepairLeavesALongerPathAlone` — a body citing the doubled `tools/alpha/tools/alpha/alpha.sh`
+  and the bare `alpha.sh`; the written body is still `the writer is \`tools/alpha/tools/alpha/alpha.sh\` and the
+  bare name is \`tools/alpha/alpha.sh\``, i.e. the doubled citation survived:
+  `and the doubled citation is collapsed, not re-doubled by the basename repair: 'the writer is
+  \`tools/alpha/alpha.sh\`' not found in: …` (exit 1).

+  `\`/alpha.sh\``, so the basename repair may not touch it and the body is unchanged):

+  `a target the history names but the tree does not hold is not a repair: expected '0', got '1'` (exit 1).

+mechanical" — its clause "A repair SHALL rewrite the citation token and nothing else" and its scenario "A

+## What Changes
+
+- `tools/issues/resolve-stale.sh`: the two rewrites record a **pair** (`old` → `new`) instead of a bullet; after
+  both loops every pair is verified — the produced body must differ from the input, the target must classify as a
+  citation the tree holds, and the old token must not survive in the new body as an `absent` citation. Only
+  verified pairs are composed into `repairs` (the bullets the comment and the report use), and a pair that fails
+  becomes an `unresolved` line, so the item is parked with the reason instead of reported repaired. The `due`
+  guard keeps its place: it now counts verified repairs.

+  (which writes full paths) keeps the current boundary rule.

+mechanical": MODIFIED — the requirement states that a repair is a change to the record, counted and commented

+# stale-citation-resolution — deltas
+
+## MODIFIED Requirements
+
+### Requirement: A citation is repaired when the repair is mechanical
+
+The resolver SHALL repair a citation whose target can be established as a fact, in this order: a unique suffix
+of a tracked path (canonicalised to that path), a rename recorded in the repository's history, or a single
+surviving file that declares the cited symbol. A repair SHALL rewrite the citation token and nothing else, and
+SHALL preserve every body marker verbatim. A basename repair SHALL NOT rewrite an occurrence that stands inside a
+longer path. A repair is a change to the record: the item SHALL count as repaired, and a comment SHALL claim a
+repair, only when the produced body differs from the input **and** every rewritten citation re-classifies as no
+longer `absent`; a rewrite that fails either test SHALL be reported as unresolved and the item parked instead.
+
+#### Scenario: A suffixed path is canonicalised
+
+- **WHEN** a body cites a class-file name that ends exactly one tracked path
+- **THEN** the citation is rewritten to that full path
+- **Case**: `resolver#suffixedCitationIsCanonicalised`
+
+#### Scenario: A renamed file is followed
+
+- **WHEN** the cited path no longer exists and the repository's history records a rename or a move of it
+- **THEN** the citation is rewritten to its successor
+- **Case**: `resolver#renamedFileIsFollowed`
+
+#### Scenario: A removed symbol is re-anchored
+
+- **WHEN** the cited file is gone and exactly one surviving file declares the cited symbol
+- **THEN** the citation is rewritten to that file
+- **Case**: `resolver#removedSymbolIsReAnchored`
+
+#### Scenario: The item's record survives the repair
+
+- **WHEN** a citation is rewritten
+- **THEN** the body's `fingerprint` and `nvid` markers are byte-identical to what they were, and no prose around
+  the citation is changed
+- **Case**: `resolver#markersSurviveTheRepair`
+
+#### Scenario: A repair is recorded
+
+- **WHEN** a citation is rewritten and the repair is verified
+- **THEN** one comment on the item names the citation before and after the repair, and the evidence for it
+- **Case**: `resolver#repairPostsOneComment`
+
+#### Scenario: A basename repair leaves a longer path alone
+
+- **WHEN** a body cites a bare file name whose only other occurrence stands inside a longer citation — the
+  doubled-directory form — and both are stale in the same body
+- **THEN** the bare occurrence is canonicalised and the longer citation is collapsed, not re-doubled, so every
+  citation in the written body resolves
+- **Case**: `resolver#basenameRepairLeavesALongerPathAlone`
+
+#### Scenario: A rewrite that changes nothing is not a repair
+
+- **WHEN** the repair ladder attempts a rewrite whose result is the input again
+- **THEN** nothing is counted as repaired, no comment claims a repair, and the item is parked with the reason
+- **Case**: `resolver#repairWithoutAChangeIsNotReported`
+
+#### Scenario: A repair is verified by re-classification
+
+- **WHEN** a rewrite replaces the cited token with a target the repository does not hold
+- **THEN** the citation is not counted as repaired and the item is parked with the reason, so the record is not
+  claimed to be repaired again
+- **Case**: `resolver#repairIsVerifiedByReclassification`
