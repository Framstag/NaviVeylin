# Design — the strip of the `./` before a tally is named

## Root cause

`tools/loop/gate.sh:173` derives a tally's file name from the suite's command by mapping `/` and space to `_` and
cutting the result at 80 characters. The profile's own compiled command begins `./gradlew`, and `.` is not mapped,
so the name begins with `.` and the file is a dotfile: `ls` and `tally/*.xml` do not list it, while `find` and
`grep -r` do. One mechanism explains the whole symptom, and the symptom is exactly that split between readers.

## The single fix

Drop the `./` prefix before the name is built:

```bash
name=$(printf '%s' "${cmd#./}" | tr '/ ' '__' | cut -c1-80)
```

Nothing else about the tally changes: the directory, the 80-character cut, the sanitising of the remaining
characters, the numbers, the time and the failure text are the ones the current code writes. A reader who matches a
tally against the command that wrote it still can, because the name is still that command minus the prefix that only
told the shell where to find the binary.

## Blast radius

- `tools/loop/gate.sh:173` (the base line; `:178` as the change leaves it) — one line and its comment. The comment
  may not name the project's own build command: the engine is held to naming no project fact (`run#engineNamesNoProjectFact`), so it says "the profile's compiled
  command is the `./`-form a program in the project root needs" and leaves the name to `tools/loop/loop.conf:139`.
  The first gate run of this change was red on exactly that, and the comment is the fix.
- `tools/loop-cases.sh` — one case (`gate#aCompiledStepsTallyIsNotHidden`), its declaration and its dispatcher line.
- `tools/loop-mutations.sh` — record `51.1`.
- `openspec/specs/agent-issue-loop/spec.md` (through this delta) — one requirement with one scenario.
- `guidelines/Backlog.md` — one sentence, in its section "The loop".

Names that change: only the tallies of `./`-prefixed commands, and the profile has exactly one
(`tools/loop/loop.conf:139`). Every command in `tools/loop/loop.conf:152`'s suite map is `tools/…`, `bash tools/…`,
or a bare script name, so no suite tally is renamed. A later item's tally directory therefore changes for one file
— the compiled step's — and it changes from a hidden `._gradlew_…xml` to a visible `gradlew_…xml`. Nothing reads a
tally by a hard-coded name: `tools/loop/measure.sh:93`, `tools/loop/run.sh:927`, `.pi/skills/fix-loop/scripts/
evidence-check.sh` C2 all search by pattern, and the run's own copy into `evidence/` keeps whatever name the file
has.

## Rollback

Revert the one line in `gate.sh` (record `51.1` is exactly that edit) and delete the case, its two declaration
lines, the record and the delta. No data migrates and no state file changes: a tally is regenerated by the next gate
run.

## Alternatives the evidence eliminated

- **Prefix every tally with `tally-`** — renames *every* file in every future evidence directory, so a reader that
  matches a tally to the suite that wrote it needs the mapping back, and the item's own record stays a copy whose
  names no longer say which command produced them. It also fixes nothing the strip does not fix: the only dotfile is
  the one the `./` created.
- **List the directory with `ls -A` wherever a count is quoted** — fixes one reader and leaves the record hidden.
  The item measured two readers missing it: a person reading `ls`, and an agent globbing `*.xml`; a run's evidence
  is read by readers the change cannot enumerate (a reviewer, a later worker, a script written next month), and the
  engine already proves the point from the other side — `evidence-check.sh` C2 exists because a reader *did* miss
  the file.
- **Strip the leading dot after sanitising** (`sed 's/^\.//'`) — the resulting name is `_gradlew_test_…xml`, whose
  leading underscore no command carries; the name would no longer be the command, which is what makes a tally
  identifiable at all.
