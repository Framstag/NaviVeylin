- [x] 9.1 Phone emulator/device (API 36, fresh install, recipe in `guidelines/Build.md` §10) — **done 2026-09-27 on `emulator-5554`** (API **37**, x86_64, de-DE, densityDpi 420). Deviation from the recipe: the run used a **permission reset instead of a data wipe** (`adb shell pm revoke com.framstag.naviveylin android.permission.ACCESS_FINE_LOCATION` + `… ACCESS_COARSE_LOCATION` on a stopped app), because `pm clear` would have deleted the 0.8 GB installed map set the search/route checks need; the dialog flow and the `SELECTED_LOCATION_ACCURACY` flag behave the same either way. The equivalent appops form the task names is `adb shell appops set com.framstag.naviveylin COARSE_LOCATION allow` / `FINE_LOCATION deny`.
  - **The dialog offers both scopes**: on the next start, "NaviVeylin erlauben, den Gerätestandort abzurufen?" with **Genau** and **Ungefähr** plus Bei Nutzung der App / Nur dieses Mal / Nicht erlauben. Choosing **Ungefähr** + **Bei Nutzung der App** leaves `ACCESS_COARSE_LOCATION: granted=true`, `ACCESS_FINE_LOCATION: granted=false`.
  - **Approximate is a working state**: with the coarse grant the app keeps a fix and follows it at coarse accuracy — `D MapCanvasVM: GPS fix acc=2000,0 bearing=- speed=- follow=false`, `D Diag/LocationService: GPS source: OS location service (FusedLocationProviderClient)`, and the fix quality degrades as specified to `D MapCanvasVM: GPS fix quality: POOR` (accuracy 2000 m > the 50 m GOOD bound). The map pans/follows on that fix and the compass shows the poor-fix tone (verified in `compass-day-night-palette` 7.3).
