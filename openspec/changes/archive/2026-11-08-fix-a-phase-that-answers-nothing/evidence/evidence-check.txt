## What the five were

Three C1s: `§7d` in `tasks.md:47`, `design.md:67` and `proposal.md:56`. Each is a **guideline section**, not a
backlog `§`-issue: `guidelines/Backlog.recipes.md:719` "Refusals, records and the landing". The check's pattern is
`§[0-9]\+` (`tools/loop/evidence-check.sh:68`), so it read the `§7` inside `§7d` as a citation of the migration's
`§ → issue` numbering, where no row 7 exists — two namespaces the check does not tell apart, and the same class the
archived changes `2026-11-06-fix-an-adoption-the-tree-refuses-is-recorded` and
`2026-11-07-fix-a-blocked-item-records-the-gate-it-ran` corrected the same way. The three pointers were repointed at
the same section by line, dropping the `§` the check misreads; no claim changed.

The one C2: the gate's own line, quoted in `evidence/gate-waived-check-rule-routes.md`, whose tally is a shell
suite's printed sum and has no JUnit XML carrier anywhere (no `tests="953"` XML exists under
`app/build/test-results` or in this evidence). The gate was run once and is not re-run for a carrier: the line now
carries "not retained as one JUnit XML" beside the numbers, which is the check's own exemption and the truth —
`evidence/check-rule-routes-gate-step.log` carries the print itself.

The one C5: the `proposal.md:94` reference was the check's own multi-file `grep -n ''` prefix (every md file's
line-number prefix is parsed as a `path:line` reference of its own file), and `proposal.md` ended without a trailing
newline — 94 lines to `grep`, 93 to `wc -l`. The file now ends with its newline.
