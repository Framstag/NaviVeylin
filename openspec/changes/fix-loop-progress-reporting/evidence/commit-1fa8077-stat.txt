    feat(loop): the wait reports itself — a run prints its child's progress, not silence (#202)
    
    A child runs in print mode, which writes only its final assistant text: measured 16 bytes at exit,
    nothing before it, on a file and on a pipe. run_child redirected the whole stream into the report file,
    so the console showed 'pick #N' and then nothing for the worker, both review rounds and the gate — a
    working item and a hung one looked the same.
    
    run_child now prints one line when a child starts, one every LOOP_PROGRESS_SECONDS (default 30), and one
    when it ends. The periodic line carries the transcript's size, the worktree's changed-file count and its
    commits since the base, all read from the tree the child writes.
    
    Case run#childReportsWhileItWaits holds a stub child on a fifo and asserts the three lines; it fails on
    the unpatched run.sh. 86/86 loop self-test cases pass offline. SKILL.md documents what a run prints.
