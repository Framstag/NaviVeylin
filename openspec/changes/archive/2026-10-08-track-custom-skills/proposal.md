# Proposal

## Why

The hand-written agent skills that `AGENTS.md` and `guidelines/Build.md` send a session to (15 directories,
187,986 bytes: `build-app`, `run-tests`, `revert-check`, `pixel-check`, `device-check`, `triage-todo`,
`cleanup-todo`, `process-failure-log`, `compose-geometry`, `provision-phone-emulator`, `release-build`,
`native-bridge-signature-change`, `update-to-current-libosmscout-master`, `openspec-open-changes`,
`openspec-proof-gap-audit`) exist on exactly one machine. `.gitignore:14` ignores `.pi/` wholesale, so a fresh
clone has none of them and no way to obtain them, and every document that names a skill names something the
clone does not have.

Relaxing that rule is not a one-line edit: 11 of the 26 directories under `.pi/skills/` are generated by the
installed OpenSpec CLI (`generatedBy: "1.14.1"` frontmatter; the 1.14.1 template set is exactly the
`workflows` list in `openspec config list`), and those must stay untracked. `openspec update` content-compares
its installed skills against its own templates and now reports drift when one was edited after generation
(`dist/core/update.js`, `findToolsWithDriftedSkills`), so a committed CLI skill invites the edit that makes
every later `update` report an unhealthy install.

## What Changes

- **`.gitignore`**: the blanket `.pi/` becomes a negative allowlist that admits the hand-written skills and
  nothing else under `.pi/` — `.pi/*` → `!.pi/skills/` → `.pi/skills/*` → `!.pi/skills/*/` →
  `.pi/skills/openspec-*/` → `!.pi/skills/openspec-open-changes/` →
  `!.pi/skills/openspec-proof-gap-audit/`.
  Measured in a scratch repository: the obvious shape (`.pi/` followed by the same negations) re-includes
  **nothing**, because a negation cannot climb out of an excluded directory; the shape above tracks
  `.pi/skills/<custom>/SKILL.md` and its supporting files, and leaves every `openspec-*` skill the CLI owns
  out. The comment block above the rule records that measurement, so it is not re-derived.
- **Track the 15 hand-written skills**: 20 files — 15 `SKILL.md` plus 5 shell scripts, 4 of them executable —
  including the two hand-written skills that carry the `openspec-` prefix. The prefix rule excludes everything
  the CLI installs, so a later OpenSpec version adding a skill (e.g. `openspec-onboard`) stays out with no edit
  here.
- **Correct the statements this makes false** — `.pi/skills/` is no longer gitignored:
  - `AGENTS.md` (the `.pi/` is gitignored — the skills are local tooling paragraph).
  - `guidelines/Build.md` §1 "Skills" (the "Each skill lives in `.pi/skills/<name>/SKILL.md` (gitignored …)"
    sentence, which becomes the split: hand-written tracked, CLI-generated untracked, and what makes a
    hand-written skill with the `openspec-` prefix visible) and §11 "Measuring a phone UI finding" (the `.pi/`
    is gitignored sentence; its surrounding "delete it before committing" advice is re-scoped to the scratch
    script, because deleting the tracked `device-check` directory is now wrong).
  - The five skill tails that say the skill itself is gitignored (`build-app`, `release-build`, `run-tests`,
    `native-bridge-signature-change`, `update-to-current-libosmscout-master`) are narrowed to the copy in
    `~/.pi/agent/skills/`.
- **No check and no capability**: this is repository tooling with no spec-level behaviour, so the change
  carries `skip_specs: true` in its `.openspec.yaml`, as the archived `github-build` and
  `remove-android-logging-from-libosmscout` changes do. Nothing enforces the split at commit time; the
  guideline states the rule and the one-line evidence that reads it back (`git ls-files .pi`).
- **Out of scope**: the rest of `.pi/` stays local — `logs/` (device captures), `extensions/`, the
  `*-instructions.json` dumps, `*.log`, `remote-pi/`. `TODO.md`'s historical entries that describe a skill as
  machine-local stay as they are (they record when that was true). No application, native, Gradle, CI or
  manifest change; `:app`, `:auto` and `:core` are untouched and both distribution flavors are unaffected,
  because the change is repository tooling, not runtime behaviour.

Additive: no existing file loses content, no API or build output changes, nothing in the app reads the skills.
Rollback: restore `.gitignore:14` to `.pi/` and `git rm -r --cached .pi/skills` — the working tree keeps every
skill file throughout.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- None. No requirement of any existing capability changes: the tracked-skill set is repository tooling, not
  behaviour the app or the car path exposes. `documentation-ownership` is untouched — the AGENTS.md edit
  corrects a fact it states, and that spec governs routing and where a rule lives, not which files the
  repository tracks.

## Impact

| file | change |
|---|---|
| `.gitignore` | blanket `.pi/` becomes the negative allowlist above (line 14) with the measurement in a comment; `.pi-subagents/` (line 15) stays as it is — the directory does not exist, and removing an ignore line is a safety regression with no benefit to this change |
| `AGENTS.md` | the `.pi/` is gitignored paragraph becomes the tracked/untracked split |
| `guidelines/Build.md` | §1 "Skills": per-skill location sentence becomes the split + the prefix exception; §11: the `.pi/` sentence and the scratch-script advice; §11: the `compose-geometry` machine-local mention |
| `.pi/skills/build-app/SKILL.md:56`, `release-build/SKILL.md:46`, `run-tests/SKILL.md:153`, `native-bridge-signature-change/SKILL.md:115`, `update-to-current-libosmscout-master/SKILL.md:200` | tail claim narrowed to the user-level copy |
| 15 directories below `.pi/skills/` | newly versioned: 20 files — 15 `SKILL.md` plus 5 shell scripts, 4 of them executable, 187,986 bytes |
| `TODO.md`, `.github/workflows/**`, `tools/**` | no change |

Not affected: any Gradle module, `app/src/**`, `auto/src/**`, `core/src/**`, the CMake/vcpkg native build, the
licence/SBOM gates, the two release flavors, CI caching. Committed skills carry the project's
GPL-3.0-or-later identifier; the MIT-licensed CLI-generated skills stay untracked, so no licence mix is
introduced and `licenses/**` is untouched.

Risks:

- A user-level copy at `~/.pi/agent/skills/<same name>` collides with the tracked one. Pi's documented rule is
  that the first discovered skill is kept and a warning is printed, but the documentation does not state which
  of the two directories is discovered first, so no document written by this change claims a precedence; the
  correction states the split and leaves the collision behaviour to Pi.
- A future hand-written skill whose directory name starts with `openspec-` needs an `!` line, or the ignore
  rule hides it. `guidelines/Build.md` §1 states that; nothing detects the omission, because this change adds
  no check.
