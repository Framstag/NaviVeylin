# Design — resolve documented skill paths in the route check

## Root cause

`tools/check-doc-routes.sh` reads two things: `AGENTS.md`'s Documentation Map region and every
`guidelines/*.md` heading. Its reference grammar is a `.md` name followed by `§<number>`; a `.pi/skills/<name>`
path has neither, so the check never sees it. `openspec/specs/documentation-ownership/spec.md` has no
requirement over the documents under `.pi/skills/` either, so nothing — not the tool, not the spec — notices
that five paths named from `guidelines/Build.md`, `guidelines/Backlog.md`, `guidelines/FeatureList.md`,
`AGENTS.md` and `openspec/config.yaml` point at directories that a rename or a deletion takes away silently.

Evidence: `.pi/issue-loop/items/13/red-test-before-fix.txt` (`2026-10-21T11:32:55Z`, `tests=14 failures=4`).

## The single fix

Extend the check it already has. `tools/check-doc-routes.sh` gains one step:

1. derive the skill set from the tree — one name per `.pi/skills/*/SKILL.md`; the directory a `SKILL.md`
   lives in is the skill, so a directory left without its contract is not one;
2. scan `AGENTS.md` and `guidelines/*.md` for `.pi/skills/<name>` tokens and resolve each name against that
   set as a whole name (`grep -qx`), so `pixel-check` is not satisfied by `pixel-check-extra`;
3. report a path that resolves to nothing through the same `::error file=…::` form the section failures use,
   and count it into the same exit-code decision and summary line.

The self-test gains the four cases and case ids plus `--case <id>`, and a versioned mutation set
(`tools/check-doc-routes-mutations.json`) makes the new guard's falsification reproducible.

Nothing else changes: the section-resolution path, the document-set derivation, the exit codes 0/1/2 and the
text-only property are as they were.

## Why this and not something else

The evidence eliminated the alternatives rather than the reverse (no option list survives gate 3):

- **A per-skill rule inventory, checked against the files** (what `widen-fix-loop` produced by hand as
  `skill-rule-inventory-{before,after}.md`) — eliminated: it needs a maintained ID table per skill and a
  reader to keep it honest, so it is a second document set with the same problem, and it is not decidable
  without the judgement the change is trying to remove.
- **A repeated-sentence detector over `.pi/skills/**`** — eliminated by measurement of the target: the 398
  lines of `fix-loop/SKILL.md` legitimately repeat stock phrases ("one mutation per check",
  "no native on the host thread"), so a similarity threshold either fires on those or is tuned until it
  cannot fail; that trade-off is a decision for the owner, not a fix.
- **Checking `openspec/config.yaml` and `tools/**` for skill paths too** — eliminated: the spec's routing
  subject is the documentation a reader is routed through (`AGENTS.md` and `guidelines/`), and the tooling
  itself fails loudly when a skill it executes is missing; widening the scan would add inputs the check has
  never read for a failure mode that cannot be silent.
- **Checking the reverse direction** (a skill no document names is reported) — eliminated: 30 of the 35
  skills under `.pi/skills/` are generated by the OpenSpec CLI and are correctly unmentioned, so the rule
  would fail on the shipped tree and its first act would be an exemption list.

## Blast radius

| site | effect |
|---|---|
| `tools/check-doc-routes.sh` | one added step; the summary line gains `, all N skill references resolve` when the documentation names skills |
| `tools/check-doc-routes-selftest.sh` | 4 cases added (14 total), case ids, `--case <id>` |
| `tools/check-doc-routes-mutations.json` | new; one mutation |
| `.github/workflows/build.yml` | the "Check documentation routes" step runs the self-test and lists the mutation set |
| the shipped tree | passes unchanged: `all 89 section references resolve, all 5 skill references resolve` |
| app code, Gradle, native | untouched — no compiled file |

A document that gains a dangling skill path after this change fails CI's "Check documentation routes" step
with `::error file=…::.pi/skills/<name> — no such skill: …`.

## Rollback

Delete the new step 6 of `tools/check-doc-routes.sh` (the block bounded by the "the skills" and "resolve the
section references" comments), restore the two `END` branches to the section-only summary, delete
`tools/check-doc-routes-mutations.json`, revert the two CI lines and the self-test's four cases; the
requirement is removed from `documentation-ownership` by a change that archives a `REMOVED` delta. No state,
no data and no generated artefact depends on the check.

## Verification

No compiled file is touched, so the project's Gradle gate is not the right instrument and is not run
(`guidelines/Build.md` §2, scope block). The structural checks are:

- `bash tools/check-doc-routes-selftest.sh` — 14 cases, exit 0;
- `bash tools/check-doc-routes.sh` — the shipped tree, exit 0;
- `bash tools/mutate.sh --mutations tools/check-doc-routes-mutations.json` — the new guard goes red and comes
  back green (`routes#aSkillPathThatNoLongerResolvesIsReported`).
