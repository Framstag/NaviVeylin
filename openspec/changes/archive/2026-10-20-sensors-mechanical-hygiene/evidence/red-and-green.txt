## 2. Two defects the cases then found in the sweep itself

```
FAIL duplicates#unauthorisedDuplicateIsCommentedNotClosed
  the report says why: 'agent/eligible' not found in: duplicates: 1 group(s)
  survivor #81 ← #82, #83 (not authorisable)
```
→ the report names the profile's label now (`not authorisable: no agent/eligible`), so a reader learns *why* the
closure stayed a person's.

```
FAIL duplicates#landedCandidateIsPrintedNotClosed
  open items a commit subject on main names: 0
```
→ the candidate list was empty although the log names the item: `git log | grep -q` per item is a pipeline whose
reader exits early, and under `pipefail` the resulting EPIPE on `git` made the test false. The ids are read out
of the log once now (`git log --format='%s' | grep -oE '#[0-9]+'`).

And one the portability gate found, not a case:

```

```
→ the engine named two profile values as literals; the variable is `authorised` and the prose is neutral.

## 5. What the sweep is not

The scheduled worker runs it; a person still owns the judgement half (`cleanup-todo`): merging two items whose
fingerprints differ (#64 into #65 on this very day), closing work that is provably done, and repairing a status a
run left behind. The sweep's candidate list is where that pass starts reading.
